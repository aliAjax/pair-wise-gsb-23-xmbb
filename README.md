# hxwl-09 半导体洁净室巡检

过滤器压差趋势监控与更换工单闭环

## 技术栈

React + Vite + TypeScript + CSS，状态持久化于 localStorage（无外部图表依赖，趋势图为内联 SVG）。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5109

## 业务闭环

1. **巡检登记**：每次登记房间、过滤器编号、初阻力（压差 Pa）、运行时长、设备状态与备注；读数只追加、不可覆盖。
2. **自动派单**：最新读数超过该区域上限，或最近 3 次非补录读数严格递增（连续上升）时，自动生成「待派工」工单；同一过滤器存在未关闭工单时不重复派单，读数继续挂到该工单上。
3. **更换前锁定**：派工后锁定当前最新读数，作为复测基准，锁定后不可更改。
4. **备件事务**：执行更换时只允许选用规格相符、在有效期内、库存充足的批次（临期可用但有提示）；新批次 `库存-1、占用+1`，旧批次 `占用-1、报废+1`（拆下报废不回库）。
5. **复测与关闭**：更换后复测/补录读数必须严格低于锁定值才允许关闭，未下降时关闭按钮禁用且给出错误提示。
6. **补录规则**：补录必须填写原因，作为独立记录追加并保留旧值；补录点不参与连续上升趋势判定。
7. **刷新一致性**：所有状态写入 localStorage，每次加载与变更后运行一致性校验（未关闭工单唯一性、批次占用=装机过滤器数、引用完整性、关闭工单复测必须下降），异常会在页内横幅提示。

## 页面

- **巡检登记**：专业字段录入 + 最近读数流水（超限/工单标签）
- **压差趋势**：过滤器列表、压差折线图（区域上限线、更换前锁定线、复测/补录点）、读数明细表
- **更换工单**：待派工 / 已派工 / 待复测看板 + 工单详情（派工→锁定→选批次→复测/补录→关闭时间线）
- **备件批次**：库存/占用/报废台账、有效期与装机占用明细对账

## 代码结构

- `src/domain.ts`：领域模型与全部纯业务逻辑（派单判定、工单状态机、批次事务、一致性校验）
- `src/seed.ts`：覆盖各闭环阶段的演示数据
- `src/store.ts`：localStorage 持久化与校验
- `src/components/`：四个页签与趋势图组件
